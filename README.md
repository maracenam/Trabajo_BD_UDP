## Instalar la base de datos

En MySQL Workbench: abrir `sql/la_mundial_completo.sql` y ejecutar todo (⚡).

Desde la consola:

```bash
mysql -u root -p --table < sql/la_mundial_completo.sql
```

El script borra y vuelve a crear la base `la_mundial`, así que se puede ejecutar de nuevo para partir de cero antes de la demo.

## Ejecutar la interfaz web

```bash
cd app
pip install -r requirements.txt
```

Variables de conexión (por defecto `127.0.0.1:3306`, usuario `root`, base `la_mundial`): `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`.

```bash
DB_PASSWORD=tu_clave python app.py
```

En Windows (PowerShell): `$env:DB_PASSWORD="tu_clave"; python app.py`. Luego abrir http://127.0.0.1:5000

## Guion de demostración

1. **Productos y stock** → buscar "Chocolate" (usa `idx_producto_nombre`).
2. **Nueva venta** → emitir ticket, elegir un cliente mayorista y vender: se aplica `precio_may` y se descuenta el stock.
3. Repetir pidiendo 9999 unidades → la venta se rechaza completa (ROLLBACK).
4. **Procesos masivos** → reajuste de 5 % a Chocolates (ver historial), reposición, generar 1000 ventas.
5. **Reportes** → ventas por día, por tipo de cliente, top productos.

## Versión en la nube: Supabase (PostgreSQL) + Vercel

- **App publicada:** https://la-mundial-bd.vercel.app
- **Base de datos:** proyecto Supabase `La Mundial - BD UDP` (región São Paulo).

| Ruta | Qué es |
|---|---|
| `supabase/01..08_*.sql` | Los mismos 8 scripts traducidos a PostgreSQL (PL/pgSQL) |
| `web/` | La interfaz web adaptada: habla con Supabase por su API REST |

Diferencias con la versión MySQL:

- `AUTO_INCREMENT` → `GENERATED BY DEFAULT AS IDENTITY`; `TINYINT(1)` → `BOOLEAN`.
- Los procedimientos almacenados pasan a **funciones PL/pgSQL**. Cada llamada es atómica: si hay un `RAISE EXCEPTION` se deshace todo (ROLLBACK automático).
- Los 3 triggers de MySQL quedan en **1 trigger** `AFTER INSERT OR UPDATE OR DELETE`.
- El índice por nombre es `lower(nombre) text_pattern_ops`, para búsquedas sin distinguir mayúsculas.
- Seguridad: RLS activado. La API pública solo puede **leer**; toda escritura pasa por las funciones `SECURITY DEFINER`, que validan los datos.

Para recrear la base en otro proyecto Supabase: abrir el **SQL Editor** y ejecutar los archivos `supabase/01` a `08` en orden.

Para correr `web/` localmente:

```bash
cd web
pip install -r requirements.txt
python app.py
```

Usa por defecto el proyecto Supabase creado; se puede cambiar con `SUPABASE_URL` y `SUPABASE_KEY`.
